# 按对话轮次回退代码

Web 的一个任务 Run 对应一个可选择的轮次；其中的审批、补充输入和继续都属于同一个 Run。服务在 Run 开始前和 Runner 清理完成后记录项目工作区快照，不依赖模型最终回答或 shell 输出猜测文件改动。

## 使用方法

1. 在中央「任务历史」选择需要处理的轮次。
2. 展开右侧「代码变更」，查看「本轮快照」的路径范围。
3. 点击「回退本轮代码」，确认后恢复这一轮开始前的文件内容。
4. 点击「撤销回退」，确认后恢复这一轮结束时的文件内容。

按轮次逐个操作，不自动连带回退之后的轮次。只修改选中 Run 的净变化路径，保留其他路径上的用户修改。同一路径被后续轮次修改时，先回退较新的轮次，再回退较旧的轮次；恢复时按相反顺序。内容或普通权限与预期快照不一致会返回409，不能强制覆盖。当前项目运行中、等待审批/补充输入或清理未完成时不可回退。

**代码回退不删除对话，也不回退 LangGraph checkpoint。** Agent 仍保留原有对话历史；后续操作可能与回退后的代码不一致，需要时新建会话。审批不会因代码回退自动通过。

快照记录的是工作区在这轮开始/结束间的净差异，包括通过 execute 修改的文件，也可能包含期间同时发生的手动编辑或后台写入。建议运行时不要同时编辑同一项目；确认路径列表后再回退。不是逐工具调用的因果审计。运行结束后新增的修改会通过内容/权限比对保护，不因为同属一个项目就全部清除。

## 记录范围与限额

- 只覆盖服务配置的宿主项目目录；/tmp、/home、/skills和额外沙箱挂载不由这份快照管理，包括映射到工作区子路径的外部目录。
- 普通文件的原始字节（包括二进制）、相对路径、目录和普通rwx权限。不依赖Git仓库，不执行git reset/stash/checkout，Git索引不改。
- 忽略任意层级的 `.git`、`.deep-agent`、`node_modules`、`.venv`、`venv`、`__pycache__`；不恢复其中内容。
- 符号链接和特殊文件不被跟随。如果本轮改了这类路径，整个轮次标记不可安全回退，不假装完整记录。
- 单文件8MiB、单次快照内容64MiB、最多5000项（含目录/根条目），去重内容对象总量512MiB。超限或读快照失败会关闭该轮回退能力，原任务仍可执行。当前工作区超限也可能阻止回退。
- 旧轮次、服务崩溃时尚未完整记录结束快照的轮次无法回退。不会从工具参数编造旧文件内容。
- 普通权限以外的ACL、xattr、所有者、时间戳、硬链接关系不在恢复契约内。常规UTF-8路径已验证；其他文件名编码未验证。

内容对象在 `state_dir/code-objects`，目录0700、文件0600；元数据与恢复日志在 `state_dir/code-history.sqlite3`（0600）。代码内容保留原始字节，可能包含项目中的敏感信息，应按私有备份保护服务目录。HTTP只返回路径/状态/版本等元数据，不把原始快照内容、对象哈希或服务令牌发给浏览器。每轮读取工作区有I/O开销；没有自动删历史，SQLite元数据仍可能随轮次增加。

## 失败与重启

每次回退/撤销都携带当前revision，旧版本、重复提交或方向错误返回409。操作前检查所有涉及路径，逐文件写入前再检查；路径访问使用目录FD和O_NOFOLLOW，目录含未记录文件时拒绝删除。

恢复日志先持久化；普通文件逐个原子替换并fsync，完成后才提交新的状态/revision。多文件操作不是一个文件系统原子事务。失败时尝试恢复操作前的内容；重启会先恢复未提交操作再接受任务。若出现第三种文件状态、根目录变化、临时文件/类型切换等不能安全确认的情况，保留日志并锁定该项目，需要人工排查，不能强行覆盖。恢复锁只影响对应项目。

服务项目互斥锁限制服务内部写入，不能锁住编辑器、其他宿主进程或后台服务。外部并发写入仍有检查与替换之间的竞态，不承诺任意外部写入下的跨文件原子性。请在项目静止时操作；409/503时检查状态与文件，不自动重试POST。

## 新接口

原 `/v1` Bearer认证不变，浏览器仍经同源BFF注入令牌。

| 方法/路径 | 含义 |
|---|---|
| GET `/v1/runs/{run_id}/code-checkpoint` | 本轮元数据、可回退状态及revision |
| POST `/v1/runs/{run_id}/code-restore` | 显式undo/redo，成功200代表文件操作已完成 |

POST仅接受：

```json
{"action":"undo","revision":"从GET获得的当前版本"}
```

`action`可为`undo`或`redo`；不接受文件路径、内容、项目目录、force等字段。401认证失败；404 Run/项目不存在；409项目占用/版本过期/文件冲突/快照不可用；422请求格式错误；503恢复失败或项目被恢复日志锁定。GET包含`status`（recording/ready/reverted/unavailable）、`available`、`files`、`reason`和可用时的`revision`/`can_undo`/`can_redo`。这是代码快照状态，不改Run终态或SSE结果。

`GET /v1/projects/{id}/active-run` 在恢复锁定时返回 `{"run":null,"blocked":true,"reason":"code_restore_recovery"}`，前端据此禁用新任务。原清理失败的占用行为继续保留。

BFF白名单对应新增 GET/POST `/api/agent/runs/{id}/code-checkpoint`、`/code-restore`；同源、JSON、请求体限制继续适用，不开放通用文件写入接口。原M0–M4只读补充范围在用户明确要求代码回退后扩展为这两个接口，Runner/沙箱架构和ask权限不重构。
